Asked for by the owner on 2026-11-14, between Sessions 3 and 4 of round 1: "please review this
repo (maybe you'd like to tweak its structure before we proceed with the new plugin development)",
and later, "maybe you'd like to check the updated workflow kit and see if you'd like to adopt any
new workflow changes from there". This file is evidence, not scope. It changes no code. The owner
chose which findings become scope; §6 says where each landed. The same chat reviewed cartoon-fx,
and that half is recorded in `mods/cartoon-fx/docs/spec/REVIEW-2026-11-14.md`.

**Method.** Every file outside `mods/` was read and mapped. The scripts were read for duplicated
logic, and the docs were checked against each other and against the tree. The workflow kit's
current `DEVELOPMENT-WORKFLOW.md` and `KICKOFF.md` were read beside this repository's copy, and
its commit history since the copy was made. The gate was run before anything was written (§1).

**Severity.** *High*: an invariant is weakened, or planned work is blocked as written.
*Medium*: a defect or debt that will cost a later session. *Low*: drift or untidiness.
*Info*: recorded, no remedy.

## 2. What holds

**The structure needs no move.** `mods/<name>/` for each mod, `templates/mod-template/` checked
by the gate like a mod, `scripts/` for the gate, `tests/` with fictional fixtures, and one
workflow copy at the root: each has one job, and a second mod drops in without touching the
others.

- **Invariant 2, a mod is self-contained:** the import scan (`scripts/imports.ts`) and
  `claude plugin validate` (`scripts/validate.ts`), per folder.
- **Invariants 3 and 4, the marketplace matches `mods/` and versions live in `plugin.json`:** the
  marketplace stage (`scripts/marketplace.ts`), with 13 tests.
- **Invariant 5, the engine's declarations stay out:** `.gitignore:5` and the marketplace stage.
- **Invariant 1, nothing private:** the hygiene stage, with 8 tests; but see F3.
- **The gate runs every stage and says how to fix one that cannot start:** `scripts/verify.ts`,
  with 8 tests.
- **The tooling's tests never collect a mod's or a fixture's tests:** `tests/verify.test.ts`.

## 3. Findings

### High

**F1. Round 1 is not closed, and new mods wait on it.** Session 4 never ran.
`docs/ARCHITECTURE.md`, `docs/USER-GUIDE.md` and `docs/MOD-KICKOFF.md` do not exist, and
`docs/BACKLOG.md` (*Deferred*, "New mods") starts a new mod only once `MOD-KICKOFF.md` does.
*Remedy:* run Session 4, after the sessions F3–F7 need.

### Medium

**F2. This repository's workflow is behind the workflow kit.** The copy was made on 2026-10-24,
at 713 lines; the kit is now 1,443, with 25 commits since. §5 lists what fits here.
*Remedy:* re-copy it, with this repository's paragraph rewritten, and bring `CLAUDE.md`'s
protocol in line.

**F3. The term list is hashes in the repository, and short words' hashes are reversible.**
`scripts/hygiene_terms.txt` holds unsalted SHA-256 hashes of single words. Hashing a dictionary
of names finds them, and the file goes public with the history. The kit now keeps the list
outside every repository, in the owner's term file, which exists on this machine.
*Remedy:* hygiene reads that file, and the repository's list is deleted. The copies in history
stay: rewriting history or accepting them is the owner's call before going public.

**F4. Hygiene judges a commit's message only after the commit.** It reads every file on every
run, and checks the messages on `HEAD`, so a bad message is found once it is committed and must
be amended. The kit checks a drafted message before the commit, reads only what a commit could
still change, and runs a full scan when the term list or the stage changes. It also catches
secrets and conflict markers, which this stage does not.
*Remedy:* port the kit's design, with its tests.

**F5. Starting a mod is a manual copy, and its instructions miss places.**
`templates/mod-template/CLAUDE.md:5-7` lists five places to rename. `mod-template` also appears in
the test file's name, `hooks/register.ts` (its greeting and the command's description),
`plugin.json`'s description, `docs/next-session-prompt.md`, the install id and verify command in
`CLAUDE.md`, and the README's install line. Nothing says to add the marketplace entry, the root
README's row, or to run `npm run types`. The template also lacks what SPEC §4 lists for a mod:
`docs/spec/`, `docs/ARCHITECTURE.md`, `docs/USER-GUIDE.md`, `types/` and `tests/fixtures/`.
*Remedy:* a script that makes a mod from the template, with a test that no `mod-template` is
left, and the template completed.

**F6. `node scripts/validate.ts` run alone does not scrub the environment.** It spawns a bare
`claude` with the caller's environment (`scripts/validate.ts:49`); only the gate passes
`hermeticEnv()` (`scripts/verify.ts:70`). `CLAUDE.md`'s Commands table presents it as the gate's
judgement, so a shell that exports `CLAUDE_CODE_PLUGIN_DIRS` judges a different set of plugins.
*Remedy:* it scrubs its own environment.

### Low

**F7. `claude` is found and spawned three ways.** `findClaude` walks `PATH`
(`scripts/verify.ts:26`); `validate.ts:49` and `types.ts:18,32` spawn a bare `claude`; the CLI
version is read in `verify.ts:40` and again in `types.ts:32`. *Remedy:* one helper in
`scripts/repo.ts`.

**F8. Smaller duplication.** `scripts/marketplace.ts` rebuilds the mods-plus-template set by hand
instead of calling `modFolders`; the "has no API declarations" message is composed in
`repo.ts` and again in `imports.ts`; the print-and-count tail of each script's `main` appears
four times; the tests' git helper is written twice. *Remedy:* folded in with F7.

**F9. The root handoff is stale.** It names cartoon-fx 0.10.1 from `3f79906`, 28 tests and 12
hooks; cartoon-fx is 0.10.3 with 36 tests and 13 hooks, pushed through `5ce1f5a`. *Remedy:*
rewritten with this review.

**F10. Docs that drift.**
- `CLAUDE.md`'s Commands table says `npm run verify -- <name>` takes one name; `plan()` takes
  several.
- `README.md`'s layout lists five scripts, not seven (`validate`, `repo`).
- SPEC §4 names a mod's module `hooks/register.tsx`; the template's is `register.ts`.
- `CLAUDE.md:16,105,152`, the template's `CLAUDE.md:7` and cartoon-fx's `CLAUDE.md:9` point at
  `docs/spec/SPEC.md`, which the close deletes.

*Remedy:* the first with F4's named stages, the rest in Session 4, as its block already plans
for the pointers.

### Info

**F11. A new CLI turns the gate red, sometimes for real.** The CLI updates itself; the laid
declarations were 2.1.310's, the CLI 2.1.323's, and it moved to 2.1.325 during the first
`npm run types`, which said so and asked for a second run. That much is working as designed.
On 2.1.325, though, cartoon-fx's `validate` and `types` failed with 20 type errors each: the
`AbovePrompt` props gained a required `isCollapsed`, and the test file's strip fixture lacked it.
A mod with no change of its own went red. Fixed in its own test-only cartoon-fx commit; the
behaviour it implies is cartoon-fx's round 3 (its review's F17).

**F12. The kit now also bans naming the owner's other projects.** SPEC decision 6 names the one
hygiene was ported from. It is in history already, so it joins F3's question before going
public; new text follows the rule once the workflow is re-copied.
